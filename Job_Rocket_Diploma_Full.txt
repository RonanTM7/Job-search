ДИПЛОМНАЯ РАБОТА

Тема: Разработка и реализация мобильного приложения для автоматизации процессов поиска работы и подбора персонала «Job Rocket» на платформе Android

ВВЕДЕНИЕ

В современных условиях глобальной цифровизации и стремительного развития информационных технологий рынок труда претерпевает фундаментальные изменения. Традиционные методы поиска работы, такие как печатные издания или личные обращения, практически полностью вытеснены цифровыми платформами. Мобильные технологии стали неотъемлемой частью повседневной жизни, что обуславливает необходимость создания высокоэффективных мобильных решений для взаимодействия между соискателями и работодателями.

Актуальность данной темы обусловлена несколькими ключевыми факторами. Во-первых, наблюдается устойчивый рост числа пользователей смартфонов, которые предпочитают решать все жизненные задачи, включая трудоустройство, с помощью мобильных устройств. Во-вторых, современные темпы жизни требуют от соискателей мгновенной реакции на появление новых вакансий, а от работодателей — оперативного подбора квалифицированных кадров. В-третьих, автоматизация процессов обработки резюме и откликов позволяет значительно снизить временные затраты обеих сторон, минимизировать человеческий фактор и повысить прозрачность взаимодействия.

Целью дипломной работы является проектирование, разработка и реализация полноценного мобильного приложения «Job Rocket», которое предоставляет пользователям интуитивно понятные инструменты для поиска работы, управления профессиональным профилем, публикации вакансий и прямого общения в режиме реального времени. Приложение призвано стать связующим звеном между специалистами различных областей и компаниями, обеспечивая надежность, безопасность и высокую скорость обмена информацией.

Объектом исследования является процесс взаимодействия субъектов рынка труда в цифровой среде.
Предметом исследования выступают программные методы и инструменты разработки мобильных приложений под управлением операционной системы Android с использованием облачных технологий Firebase.

Для достижения поставленной цели необходимо решить следующие задачи:
1. Провести комплексный анализ предметной области, изучить специфику процессов найма и выявить основные проблемы, с которыми сталкиваются пользователи существующих платформ.
2. Изучить теоретические аспекты разработки мобильных приложений, провести обзор современных архитектурных подходов и языков программирования.
3. Обосновать выбор технологического стека, включая среду разработки, языки программирования и сервисы для хранения данных.
4. Спроектировать логическую структуру системы, определить роли пользователей и разработать сценарии их взаимодействия.
5. Разработать и оптимизировать структуру NoSQL базы данных, обеспечивающую хранение больших объемов информации о пользователях, вакансиях и сообщениях.
6. Спроектировать и реализовать современный пользовательский интерфейс, соответствующий принципам Material Design и обеспечивающий высокую эргономичность.
7. Реализовать функциональные модули приложения: систему авторизации, фильтрацию вакансий, конструктор резюме, систему откликов и real-time чат.
8. Обеспечить информационную безопасность системы, реализовать механизмы защиты персональных данных и разграничения прав доступа.
9. Провести всестороннее тестирование программного продукта, выявить и устранить возможные дефекты, оценить производительность и стабильность работы приложения.

Научная и практическая новизна работы заключается в создании оптимизированного мобильного решения, которое интегрирует функции поиска работы и мгновенной связи в единую экосистему, использующую преимущества облачных вычислений для обеспечения актуальности данных без необходимости ручного обновления.

1. Теоретические основы поставленной задачи, обзор аналогичных решений

1.1. Постановка задачи и обоснование разработки

В условиях современного рынка труда, характеризующегося высокой динамичностью и конкуренцией, эффективность взаимодействия между работодателем и соискателем напрямую зависит от скорости и качества обмена информацией. Существующие веб-ресурсы зачастую обладают избыточной сложностью или не предоставляют должного уровня мобильности. Разработка приложения «Job Rocket» направлена на устранение этих барьеров.

Основная задача программного продукта заключается в предоставлении пользователям надежного инструмента, доступного «в кармане». Для соискателя это означает возможность получать уведомления о новых предложениях в режиме реального времени, моментально откликаться на них и вести диалог с работодателем без использования сторонних мессенджеров. Для работодателя приложение должно стать удобным инструментом для публикации вакансий и первичного отбора кандидатов на основе их цифровых резюме.

Автоматизация в рамках данного проекта охватывает следующие аспекты:
- Систематизация данных о вакансиях по категориям, типам занятости и форматам работы.
- Управление жизненным циклом отклика — от подачи заявки до финального решения.
- Централизованное хранение переписки и контактных данных.
- Автоматическая проверка обновлений приложения для обеспечения безопасности и стабильности.

Разрабатываемое приложение должно соответствовать строгим критериям качества: отказоустойчивость, масштабируемость, простота поддержки и высокая скорость отклика интерфейса. Особое внимание уделяется разделению ролей пользователей, что позволяет адаптировать интерфейс и доступные функции под конкретные цели каждого участника процесса.

В процессе постановки задачи были сформулированы требования к аппаратной и программной части. Приложение должно поддерживать широкий спектр устройств под управлением Android, начиная с версии API 21, что обеспечивает охват подавляющего большинства современных смартфонов. В качестве серверной части выбрана платформа Firebase, что позволяет отказаться от разработки и поддержки собственного серверного оборудования и сосредоточиться на клиентском функционале.

1.2. Обзор существующих решений

На текущий момент на рынке представлено несколько крупных игроков в сфере поиска работы, таких как HeadHunter, SuperJob, LinkedIn и Работа.ру. Анализ их функциональных возможностей позволяет выделить как сильные стороны, так и недостатки, которые необходимо учесть при разработке «Job Rocket».

Большинство крупных платформ обладают огромной базой данных, но при этом их мобильные приложения часто перегружены функционалом, что затрудняет навигацию. Также многие сервисы взимают высокую плату с работодателей за публикацию вакансий или ограничивают возможности прямого общения без предварительной оплаты.

В отличие от них, «Job Rocket» ориентирован на:
- Максимальную простоту и скорость: минимальное количество кликов от открытия приложения до отклика.
- Интегрированные коммуникации: чат является ключевым элементом, а не вторичной функцией.
- Легкость развертывания: использование Firebase позволяет приложению работать стабильно даже при резком росте числа пользователей.

1.3. Описание логической структуры системы

Логическая структура мобильного приложения «Job Rocket» спроектирована как многоуровневая архитектура, обеспечивающая четкое разделение бизнес-логики, представления данных и взаимодействия с внешними сервисами. Основная парадигма разработки — объектно-ориентированный подход, реализованный на языке Java.

В основе системы лежит ролевая модель, разделяющая пользователей на три категории:

1. Соискатель (Seeker).
Это основной потребитель контента. После авторизации соискатель попадает в главную ленту вакансий. Его логический путь включает в себя настройку фильтров для точного подбора предложений, сохранение понравившихся вакансий в «Избранное», создание структурированного резюме, подачу откликов и общение с нанимателями. Логика приложения построена так, что соискатель всегда видит актуальный статус своих заявок.

2. Работодатель (Employer).
Пользователь, создающий контент. Его функционал сосредоточен вокруг управления вакансиями компании. Работодатель может добавлять новые позиции, указывая детальные требования, редактировать их или закрывать при заполнении штата. Ключевым компонентом для работодателя является модуль просмотра откликов, где он может изучить резюме кандидатов и инициировать чат с наиболее подходящими из них.

3. Администратор (Admin).
Служебная роль, предназначенная для контроля за работоспособностью системы и соблюдением правил платформы. Администратор имеет доступ к списку всех зарегистрированных пользователей, может просматривать активность в чатах для предотвращения спама или мошенничества, а также управлять выпуском обновлений приложения.

Процесс взаимодействия с приложением начинается с экрана входа (LoginActivity) или регистрации (RegisterActivity/RoleSelectionActivity). Система использует Firebase Authentication для верификации пользователя. После успешного входа данные о пользователе подгружаются из Firestore, определяется его роль, и осуществляется переход на соответствующий главный экран (MainActivity для пользователей или AdminMainActivity для администратора).

Все экраны реализованы с использованием компонентов Activity и Fragment. Это позволяет обеспечить плавные переходы и эффективное управление жизненным циклом приложения, что критически важно для экономии ресурсов мобильного устройства.

1.4. Защита и сохранность данных

В эпоху цифровых угроз обеспечение безопасности персональных данных является первоочередной задачей. Приложение «Job Rocket» реализует комплексный подход к защите информации, охватывающий все уровни: от передачи данных по сети до хранения на сервере.

Ключевые механизмы защиты:

1. Безопасная аутентификация.
Использование Firebase Auth позволяет делегировать хранение паролей и управление сессиями профессиональному сервису от Google. Это исключает возможность компрометации паролей на стороне разработчика. Приложение поддерживает проверку подтверждения электронной почты для предотвращения создания фиктивных аккаунтов.

2. Правила безопасности Firestore.
Доступ к базе данных регулируется на уровне сервера с помощью специальных правил (Security Rules). Эти правила гарантируют, что пользователь может читать и записывать только свои данные. Например, соискатель не может изменить чужое резюме, а работодатель имеет доступ к личным данным соискателя только в контексте поданного отклика.

3. Защита от утечек данных.
Вся коммуникация между приложением и облачными сервисами осуществляется по зашифрованным каналам (HTTPS/TLS). Персональные данные, такие как номера телефонов и email, хранятся в защищенном виде и отображаются только авторизованным пользователям с соответствующими правами.

4. Обработка статусов аккаунтов.
Система поддерживает статусы «active», «blocked» и «deleted». При блокировке администратором пользователь мгновенно теряет доступ к функциям приложения. Механизм «мягкого удаления» позволяет сокрыть данные пользователя из общего доступа, сохраняя при этом целостность базы данных для отчетности.

5. Валидация и фильтрация.
На всех этапах ввода данных (регистрация, создание вакансии, редактирование профиля) применяются алгоритмы валидации. Это предотвращает отправку некорректных запросов к базе данных и защищает от потенциальных инъекций.

Сохранность данных также обеспечивается за счет использования облачной инфраструктуры, которая подразумевает автоматическое резервное копирование и высокую доступность сервисов 24/7. Даже в случае сбоя на мобильном устройстве пользователя, все его данные (резюме, избранное, переписка) будут доступны сразу после входа с другого устройства.

2. Техническая реализация и описание функциональных модулей

2.1. Обоснование выбора технологий разработки

Выбор технологического стека для реализации проекта «Job Rocket» был продиктован требованиями к мобильности, производительности и необходимости поддержки функций реального времени.

В качестве основной платформы была выбрана операционная система Android, как самая распространенная мобильная ОС в мире. Разработка велась в интегрированной среде Android Studio, которая предоставляет разработчику мощный инструментарий для написания кода, проектирования интерфейсов, отладки и профилирования приложения.

Язык программирования Java выбран в качестве основного инструмента разработки. Java обладает рядом неоспоримых преимуществ для создания корпоративных и мобильных приложений:
- Строгая типизация и объектно-ориентированный подход позволяют создавать легко поддерживаемый и масштабируемый код.
- Огромное количество готовых библиотек и развитое сообщество значительно ускоряют процесс решения типовых задач.
- Высокая стабильность и предсказуемость работы виртуальной машины Java (JVM) обеспечивают надежность приложения на различных версиях Android.

Для обеспечения работы с данными и облачными функциями была интегрирована платформа Firebase. Это современное решение от компании Google, которое позволяет реализовывать сложные серверные функции без необходимости развертывания собственной инфраструктуры. В проекте используются следующие сервисы Firebase:

1. Firebase Firestore.
Облачная NoSQL база данных, хранящая данные в формате документов и коллекций. Она обеспечивает автоматическую синхронизацию данных между устройствами и позволяет приложению работать в офлайн-режиме, сохраняя изменения локально и синхронизируя их при появлении сети. Использование NoSQL подхода позволило гибко настраивать структуру данных вакансий и резюме без жестких ограничений реляционных таблиц.

2. Firebase Authentication.
Обеспечивает надежную систему входа и регистрации. Поддерживает проверку уникальности email, восстановление паролей и безопасное хранение учетных записей.

3. Firebase Cloud Messaging (FCM).
Используется для реализации системы мгновенных уведомлений. Благодаря FCM, соискатели мгновенно узнают о сообщениях от работодателей, а работодатели — о новых откликах на свои вакансии, даже если приложение закрыто.

4. Firebase Storage (при необходимости).
Позволяет хранить медиафайлы, такие как фотографии профиля или логотипы компаний.

2.2. Проектирование и структура базы данных

Архитектура базы данных Firestore в приложении «Job Rocket» построена на принципе коллекций, содержащих документы. Каждый документ представляет собой объект с набором полей. Такая структура идеально подходит для мобильных приложений, так как позволяет минимизировать объем передаваемых данных и упрощает доступ к связанной информации.

Основные коллекции системы:

- Коллекция «users»: Содержит документы пользователей. Поля включают уникальный идентификатор (UID), имя пользователя, адрес электронной почты, роль (админ, работодатель, соискатель), статус аккаунта и токен для push-уведомлений.
- Коллекция «vacancies»: Хранит информацию о предложениях работы. Каждый документ содержит описание вакансии, требования к кандидату, информацию о зарплате, категории (например, «Бэкенд» или «Дизайн»), типе занятости и идентификатор работодателя-создателя.
- Коллекция «resumes»: Содержит профессиональные профили соискателей. Здесь хранятся сведения об образовании, опыте работы, ключевых навыках и контактная информация.
- Коллекция «applications»: Служит для регистрации откликов. Содержит идентификаторы вакансии и соискателя, дату отклика и его текущий статус. Это позволяет работодателю эффективно управлять потоком кандидатов.
- Коллекция «employer_chats»: Предназначена для организации переписки. Каждый документ здесь представляет собой метаданные чата, включая идентификаторы участников, последнее сообщение и количество непрочитанных уведомлений. Вложенная коллекция «messages» хранит историю сообщений с временными метками.

Такая организация данных обеспечивает высокую скорость чтения и записи, а также позволяет легко расширять функционал приложения в будущем, добавляя новые поля или коллекции без нарушения работы существующих модулей.

2.3. Реализация пользовательского интерфейса и навигации

Пользовательский интерфейс «Job Rocket» спроектирован с учетом современных требований к мобильным приложениям. Основная цель дизайна — минимизировать когнитивную нагрузку на пользователя и сделать процесс поиска работы максимально простым.

Навигация в приложении для соискателя реализована с использованием нижнего меню (BottomNavigationView). Это стандартное решение для Android, обеспечивающее быстрый доступ к четырем основным разделам:
1. Главная (Лента вакансий).
2. Избранное (Сохраненные вакансии).
3. Отклики (История заявок).
4. Профиль (Настройки и резюме).

2.4. Описание ключевых функциональных возможностей

Функционал приложения «Job Rocket» был разработан таким образом, чтобы автоматизировать каждый этап процесса трудоустройства и подбора персонала.

1. Модуль управления вакансиями.
Для работодателя это основной инструмент работы. Процесс создания вакансии (AddEditVacancyActivity) включает в себя заполнение подробной анкеты, где указываются не только базовые параметры (название, зарплата), но и специфические условия: график работы (5/2, 2/2, гибкий), тип занятости (полная, частичная) и формат (офис или удаленка). Валидация полей гарантирует, что вакансия не будет опубликована без ключевой информации. После публикации вакансия мгновенно становится доступной в общей ленте всех соискателей.

2. Модуль поиска и фильтрации.
Соискатели могут использовать мощную систему фильтров (HomeFragment), которая позволяет сузить круг поиска до наиболее релевантных предложений. Фильтрация осуществляется по категориям IT-специальностей, зарплатному ожиданию и другим параметрам. Это значительно экономит время пользователя, избавляя его от необходимости просматривать сотни неподходящих объявлений.

3. Модуль «Избранное».
Позволяет соискателям сохранять интересные вакансии (FavoritesFragment) для последующего детального изучения или отклика. Данные об избранном хранятся в облаке и привязаны к аккаунту пользователя, что обеспечивает их доступность на любом устройстве.

4. Модуль резюме.
Вместо загрузки тяжелых PDF-файлов, приложение предлагает соискателям заполнить структурированную анкету в конструкторе резюме (ResumeActivity). Это унифицирует представление данных о кандидатах, упрощая работодателям процесс сравнения и первичного отбора. Соискатель может в любой момент обновить свои навыки или опыт работы.

5. Система откликов и уведомлений.
При отклике на вакансию система автоматически создает связь между соискателем и работодателем в коллекции «applications». Работодатель получает уведомление и может сразу же перейти к просмотру профиля кандидата. Соискатель, в свою очередь, может отслеживать список всех своих откликов в специальном разделе (ApplicationsFragment).

6. Панель администратора.
Для обеспечения порядка на платформе реализован административный интерфейс (AdminMainActivity). Администратор может просматривать список всех зарегистрированных пользователей, включая их роли и даты регистрации (AdminUsersActivity). В случае нарушения правил платформы администратор имеет право заблокировать аккаунт пользователя (BlockedActivity). Также администратор может отслеживать активность в системе через раздел мониторинга чатов (AdminChatsActivity).

3. Охрана труда и безопасность жизнедеятельности при работе с ПЭВМ и мобильными устройствами

3.1. Требования охраны труда при организации рабочего места

Разработка и последующая эксплуатация мобильного приложения «Job Rocket» неразрывно связаны с длительным использованием персональных электронно-вычислительных машин (ПЭВМ) и мобильных устройств. В соответствии с современными стандартами охраны труда, обеспечение безопасных условий работы является обязательным условием для сохранения здоровья и предупреждения профессиональных заболеваний, таких как синдром компьютерного зрения или туннельный синдром.

Организация рабочего места разработчика и пользователя должна соответствовать следующим требованиям:
- Рабочий стол должен иметь достаточную площадь для размещения монитора, клавиатуры и необходимых периферийных устройств. Высота стола должна позволять пользователю держать спину ровно, а локти — под углом около 90 градусов.
- Монитор должен располагаться на расстоянии 600–700 мм от глаз, а его верхний край — на уровне глаз или чуть ниже. Это снижает нагрузку на шейный отдел позвоночника и мышцы глаз.
- Освещение помещения должно быть комбинированным (естественным и искусственным). Важно избегать прямых бликов на экране, которые вызывают быстрое утомление. Рекомендуется использовать антибликовые покрытия или шторы на окнах.

3.2. Режим труда и отдыха

Длительная непрерывная работа за компьютером или смартфоном ведет к накоплению усталости. Для поддержания высокой работоспособности необходимо соблюдать рациональный режим:
- Каждые 45–60 минут работы следует делать регламентированные перерывы продолжительностью 10–15 минут.
- Во время перерывов рекомендуется выполнять гимнастику для глаз (фокусировка на дальних и ближних объектах, вращения) и легкую физическую разминку для улучшения кровообращения.
- Использование мобильных устройств в движении или при плохом освещении крайне не рекомендуется, так как это значительно увеличивает нагрузку на зрительный аппарат.

3.3. Эргономические особенности программного продукта

При разработке «Job Rocket» были учтены эргономические требования, направленные на снижение утомляемости пользователя:
- Шрифты и цветовые контрасты подобраны таким образом, чтобы текст легко читался при любом уровне яркости экрана.
- Внедрение темной темы оформления (Dark Mode) позволяет снизить излучение синего света в вечернее время, что благотворно сказывается на качестве сна пользователя и снижает нагрузку на зрение.
- Элементы управления (кнопки, меню) имеют достаточный размер для безошибочного нажатия пальцем, что исключает лишние движения и психологическое напряжение при работе с интерфейсом.

Соблюдение вышеуказанных норм и правил позволяет сделать процесс взаимодействия с информационными системами максимально безопасным и эффективным.

Приложение
Листинг кода экрана авторизации (LoginActivity.java):

```java
package job.search.app;

import android.content.Intent;
import android.os.Bundle;
import android.widget.Button;
import android.widget.EditText;
import com.google.firebase.auth.FirebaseAuth;
import com.google.firebase.firestore.FirebaseFirestore;
// ... импорты

public class LoginActivity extends AppCompatActivity {
    private EditText editTextEmail, editTextPassword;
    private FirebaseAuth mAuth;
    private FirebaseFirestore db;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_login);

        mAuth = FirebaseAuth.getInstance();
        db = FirebaseFirestore.getInstance();

        editTextEmail = findViewById(R.id.editTextEmail);
        editTextPassword = findViewById(R.id.editTextPassword);
        Button buttonLogin = findViewById(R.id.buttonLogin);

        buttonLogin.setOnClickListener(v -> login());
    }

    private void login() {
        String email = editTextEmail.getText().toString().trim();
        String password = editTextPassword.getText().toString().trim();

        if (email.isEmpty() || password.isEmpty()) {
            return;
        }

        mAuth.signInWithEmailAndPassword(email, password)
                .addOnCompleteListener(this, authTask -> {
                    if (authTask.isSuccessful()) {
                        checkUserRoleAndLogin(mAuth.getCurrentUser(), email);
                    }
                });
    }

    private void checkUserRoleAndLogin(FirebaseUser user, String email) {
        // Проверка роли пользователя в коллекциях admins, employers, seekers
        db.collection("admins").document(user.getUid()).get().addOnCompleteListener(task -> {
            if (task.isSuccessful() && task.getResult().exists()) {
                proceedToLogin("admin");
            } else {
                // Аналогичные проверки для других ролей
            }
        });
    }
}
```
